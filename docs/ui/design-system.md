# Studio 设计系统

Studio 采用内容优先的紧凑工作台：连续剧本区、按对象组织的属性区、可辨选区和可信保存反馈。视觉顺序为当前内容与选区、文档主动作、属性和上下文、导航、技术元信息。名称先于 ID、路径和贡献键，技术信息在详情中完整查看与复制。

识别特征是文稿、舞台和属性之间可追溯的上下文：作者能辨认当前对象、预览来源及本次写入。浅蓝浅色与暮蓝紫深色延续同一品牌，连续内容、工具与属性通过表面和细分隔分层。

## 字体、密度与尺度

中央资料表单使用有界阅读宽度，按作者任务分组。常用字段和当前保存优先，画布尺寸、颜色和较少使用的设置按需展开。只有字段对照有帮助且空间足够时使用并排，窄窗按阅读顺序排列。

Studio 使用 Geist Variable，Windows 中文依次回退到 Segoe UI、Microsoft YaHei、sans-serif；Monaco 保持等宽字体。正文和输入保留可读尺度，复杂属性通过分组与渐进展开安排。

| 内容 | 字号/行高 | 字重 |
|---|---|---|
| 普通 UI 内容、目录、文档标签、菜单、标准字段值 | 14/20px | 400 |
| 面板与对象标题 | 14/20px | 500；必要重点 600 |
| 紧凑按钮与输入、字段标签、帮助说明 | 12/16px | 内容 400，按钮与标签 500 |
| 状态、计数、序号、次级元信息 | 11/16px | 400 |
| 标准对话框标题 | 18/28px | 600 |
| 连续文稿默认正文 | 14/21px | 正文 400，说话人 500 |

开发者按职责选择标准或紧凑角色，局部标题显式声明层级；关键操作和长正文保持可读。文稿尊重作者已保存的字体与字号，默认行高为字号的 1.5 倍。Player 使用作品文字规则，Monaco 使用编辑器个人设置，专业画布保持自身设计尺寸。

设计使用一个专业桌面密度。间距采用 4px 基础节奏，按组内、面板和分区层级展开。长正文、错误和保存影响自然换行；长对象名可省略，并通过 Tooltip 或详情提供全文。placeholder 提供格式或示例，Field 提供真实标签。短属性字段使用有界宽度，长文本、列表、比较和画布分别确定内容宽度。

人物资料先呈现名称、简介与创作设定、外观说明和参考图；默认演出独立收纳，身份等设定按需展开。正文独立滚动，底部持续显示当前人物的保存主动作及「仅应用到工作区」次动作。忙碌、无效输入、冲突和缺失来源在所属区域说明，保留输入及可读详情；浅色与暮色使用同一层级和操作语义。

恢复输入区分可继续编辑的原人物表单与需要作者明确继续的尚未创建草稿；来源失效保留说明及可复制详情。素材选择器的导入与已有结果同级可达，本次成功浏览显示明确返回入口和持续可读的失败回执。应用或取消后恢复原字段焦点及滚动；字段首次绑定或素材改名继续使用同一字段身份。

素材库将查询、排序、计数与导入组织为紧凑工具区，回执历史、失败详情和批量动作按需展开；低高度底栏保留完整紧凑素材行，较大浏览空间沿用卡片及类型预览。批量勾选、当前主对象、预览版本和固定属性来源分别可辨。「查看本批」与「返回素材浏览」说明临时范围，「聚焦浏览/还原浏览」沿用 Dock 的局部最大化。人物参考图和共同差分的选择、导入及版本操作在所属字段内继续完成。

| 元素 | 尺寸 |
|---|---|
| 紧凑工具 / 字段 | 24–28px / 28–32px 高，按职责选择 |
| 常用图标与行内按钮命中区 | 16px 图标；至少 28×28px 命中区 |
| 左右工具区宽度 | 首次默认 320px，下限 240px |
| 常规中央工作面 | 下限 480px；专业工作面按实际操作确定下限 |
| 圆角 | 紧凑标记 4px，控件/素材框 6px，浮层 8px，对话框 12px |

工作区拼接边采用直边。连续列表、Inspector 和工具组通过留白、表面和细分隔分层；脱离文档平面的浮层使用边框与阴影。Lucide 图标保持同一描边。舞台沿作品视觉呈现。

宽度不足时优先保留活动编辑和草稿，辅助区临时收纳，恢复空间后还原。工具所属区域、中央分屏与恢复规则见[工作台交互](workbench.md#布局与文档)。

正文和关键标签目标对比度至少 4.5:1，识别交互所必需的边界、状态和焦点与相邻表面目标至少 3:1。disabled 表示真实不可交互内容，原因使用正常对比说明；只读内容保持可读和可复制。实际 CSS、透明度、继承、Portal 和系统字体由实际消费者检查。

Studio 主题仅覆盖 Studio 根及所属 Portal。Player、Monaco 和插件贡献 DOM 使用自己的作用域；M01 保存 Studio 明暗偏好，作品阅读模板继续由 M08 提供。

短反馈 Message 浮在工作台上方，出现、更新或关闭时保持编辑区位置与尺寸。标题、正文与操作使用对应语义前景，背景由 80% 语义表面与 20% popover 混合，边框使用轻语义色；浅色保持淡绿、淡红、淡琥珀及淡蓝，暮色使用所属主题令牌。语义同时由图标和文字表达，错误使用圆圈 ×，信息使用圆圈 i。Message 的尺寸、计时与键盘行为由[组件规则](components.md#当前控件选择)维护。

指令的媒体、声音和控制分类使用局部图标、标记或浅色分区，并保留文字类型名称。当前任务使用一个明确主动作；普通次动作使用轻表面或 outline，重复管理动作使用 ghost。

## 状态与动效

| 状态 | 表达规则 |
|---|---|
| hover/pressed | 使用表面变化，文本和控件位置稳定 |
| focus-visible | 2px 焦点线，通常 2px offset；布局为其保留空间 |
| selected/active | 底色加边标记或勾选，焦点可同时呈现 |
| disabled | 使用真实禁用语义，显示可访问原因 |
| read-only | 正常可读、可选择和复制，显示所属原因 |
| loading | 就地 busy 或稳定尺寸骨架，重复提交进入 pending |
| error | 字段或对象旁持续说明原因、恢复与保留输入 |
| success | 实际回执更新局部状态，必要时短 Toast |
| mixed/partial | 显示多个值及半选语义，仅提交实际编辑字段 |

问题状态同时表达严重性和结果依据。「需要重新检查」「检查尚未完成」与当前有效结果分别显示；检查失败保留带状态的旧结果，空结果只有在检查有效时才表示当前没有问题。操作失败在列表中使用批次或任务摘要，原始明细由所属工作面维护。「已忽略本次」表示作者暂时移出该次失败摘要，原回执与失败事实继续保留，已忽略项可重新关注。Dock 名称与数量、紧凑搜索与筛选、条目和按需详情分别承担层级；浅色与暮色均使用图标、文字和状态标记表达含义。

hover/focus 色彩过渡 80–120ms，浮层 opacity 可用 120–160ms，排序反馈约 180–220ms。动效按实际属性限定，编辑区几何与文字输入立即响应。`prefers-reduced-motion` 使用直接定位并保留状态标记。未知进度显示不确定状态，完成反馈来自实际回执。
